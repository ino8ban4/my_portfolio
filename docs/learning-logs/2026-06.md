## Issue #22: blog-api基盤実装（Fastifyサーバー起動 + /healthエンドポイント）

### やったこと
- `src/index.ts` を作成、Fastifyサーバー起動
- `GET /health` エンドポイント実装
- Docker Compose経由でホストからcurl確認済み

### 理解の証明

#### `0.0.0.0` vs `127.0.0.1`
- 理解内容: `0.0.0.0` は全ネットワークインターフェースで待機、`127.0.0.1` はループバックのみ
- 判断基準: コンテナ外からアクセスするには `0.0.0.0` が必須
- 実装での選択理由: Docker Composeでホストからアクセスするため

#### `async/await` + `try/catch`
- 理解内容: `app.listen()` 失敗時にエラーをキャッチしてプロセスを明示的に終了する
- 判断基準: catchしないとエラーが握りつぶされる可能性がある
- 実装での選択理由: ポート競合等の起動失敗を確実に検知するため

#### `logger: true`
- 理解内容: JSON形式でログを標準出力する
- 判断基準: Datadog・Grafana Loki等のログ収集ツールがJSON形式を自動パースできる
- 実装での選択理由: 将来のminikubeデプロイ時の運用を見据えて

### トラブルシューティング
- `docker compose restart` ではマウントが更新されない → `down → up` が必要
- 名前付きボリュームはコンテナ再作成でリセットされる → `npm install` が必要

## Issue #23: Swagger導入（API仕様書の自動生成）

### やったこと
- `@fastify/swagger` と `@fastify/swagger-ui` を `index.ts` に組み込む
- `http://localhost:3000/docs` でSwagger UIの表示確認

### 理解の証明

#### `app.register()` に `await` をつける理由
- 理解内容: `register()` はPromiseを返す非同期処理なので `await` が必要
- 判断基準: `await` なしだと登録完了前に次の処理が走る
- 実装での選択理由: swaggerが未登録のままルートが登録されるのを防ぐため

#### swaggerをルート登録より前に行う理由
- 理解内容: Fastifyはプラグイン登録時点で存在するルートしかSwaggerに含めない
- 判断基準: 登録順序がAPI仕様書の内容に直結する
- 実装での選択理由: `/health` をSwaggerに表示するため

#### `/docs/json` の用途
- 理解内容: OpenAPI仕様のJSONが返ってくる
- 判断基準: 他ツール（Postman・Insomnia）へのインポートやAPIクライアント自動生成に使える
- 実装での選択理由: チーム開発での利便性を考慮

## Issue #24: Prisma + DB接続

### やったこと
- `prisma/schema.prisma` にPostモデルを定義
- `prisma migrate dev --name init` でマイグレーション実行
- `src/prisma.ts` でPrismaClientを初期化
- Prisma Studioでテーブル確認

### 理解の証明

#### `migrate dev` vs `migrate deploy`
- 理解内容: devは開発環境でマイグレーションファイルを生成、deployは本番環境で既存ファイルを適用するだけ
- 判断基準: 本番環境でスキーマを勝手に変えられると困るのでdeployは適用のみ
- 実装での選択理由: 開発中はdevで生成、Gitで管理してdeployで本番適用

#### PrismaClientをシングルトンで管理する理由
- 理解内容: 複数インスタンスを作るとDBコネクションプールが枯渇する
- 判断基準: Javaのシングルトンパターンと同じ考え方
- 実装での選択理由: `export default` で1インスタンスを使い回す

#### `DATABASE_URL` の `db` ホスト名
- 理解内容: Docker ComposeのサービスA名で、コンテナ間通信で名前解決できる
- 判断基準: `docker-compose.yml` の `db:` サービスがそのままホスト名になる
- 実装での選択理由: コンテナ間通信はサービス名で接続するのがDocker Composeの規約
